Codex 執行

每件工作怎麼跑

crew 用參數陣列開 Codex，不經過 shell；工作內容從 stdin 給，不放在參數裡（參數會出現在 ps）。第一次是全新執行，之後同一個角色的工作用 resume 接續同一條對話，跟 Claude 角色的「喚醒」一樣；輪替時開新的對話。

沙箱一律由 crew 在參數裡指定，所以會蓋過任何設定檔裡的 danger-full-access；approval_policy="never" 讓超出沙箱的指令直接失敗，不會卡著等人按。shell_environment_policy.inherit="core" 讓 Codex 跑的指令只拿到基本環境變數，拿不到你的 API key。

--ignore-user-config 讓你的 config.toml 整份不載入，crew 不必讀 MCP 名稱，也不碰任何帶 env 原值的輸出。--ignore-rules 讓你 ~/.codex/rules 裡的指令規則不載入：規則允許的指令會跑在沙箱外，沒加這個參數時，read-only 的角色也能 git commit（實測見上表）。技能清單在每個 session 第一次用到時掃一次技能根目錄（~/.codex/skills、~/.agents/skills、~/.codex/plugins/cache、repo 的 .codex/skills 和 .agents/skills）。功能開關是 0.162.1 實測過的名稱；Codex 改版後不認得的名稱會被忽略，crew 記下測過的版本，版本變了就在模型分頁標出來。

設計稿 artifact（2026-10-30 確認）

你要確認的東西都要有 artifact。設計稿的做法照提案第 2 版（claude.ai/artifact/Sfo8Vq89Fo96z5pgdnq1b5）：一個 PRD 一個 artifact，裡面放這個 PRD 的所有設計稿；有畫面的可以點，沒有畫面的顯示文字；核准和退回都在 artifact 裡按；artifact 由大腦發佈；決定由大腦轉給 crew。

資料

  • mockup 不放看板：每個角色都會讀看板，所以看板上的設計稿只多一個 crew_mockup: { version, mark, bytes }。HTML 放在 .crew/designs/<PRD 代號>/SCR-001.json（{ id, version, html }），PRD 代號由 PRD 的路徑轉成。
  • UI/UX 怎麼交：add_design 多一個 html，有畫面（screen）的必填，沒有畫面（none）的不能填。新的 add_mockup { id, html } 用來替已經有的設計稿補上或換掉 mockup，版次加 1。設計稿的指紋（designMark）把 mockup 也算進去，所以換了 mockup，原本的決定就不算數了。
  • 檢查：mockup 不能是空的，最多 200,000 字。不能引用外部資源，也就是 src、href、url()、@import 指到 http(s):// 或 // 開頭的網址。不能用 fetch、XMLHttpRequest、WebSocket、EventSource、sendBeacon。和看板上其他文字一樣，先遮蔽秘密。

  • review.ts 是純函式，由看板、決定和 mockup 清單產生 .crew/designs/<PRD 代號>/index.html。

待你決定頁（2026-10-30 確認）

設計稿 artifact 擴大成「待你決定頁」。做法照提案（claude.ai/artifact/8weFeTBvRZ76sjmYbRChpV），你確認的三件事：一個 PRD 一頁、分三個分頁；模型的事和大腦的建議留在面板；角色問問題時可以附選項。

頁面

  • 一個 PRD 一頁：分成「PRD 草稿」「設計稿」「問題」三個分頁，有等你決定的分頁標出件數。這一頁跟著 PRD 的路徑走：草稿在等你確認時就發佈；確認開始之後，同一個連結繼續放設計稿和問題。
  • PRD 草稿：顯示草稿全文（純文字排版，不執行任何 HTML）、PM 和 UI/UX 的審查結果、大腦的摘要。按鈕：［確認，開始］和「要改的地方」。
  • 問題：只放角色和 crew 問的問題。每題附上它問的項目和標題；角色給了選項就變成按鈕，另外一定可以自己寫。設計稿的核准在「設計稿」分頁；大腦自己的問題、大腦的建議（tune）和模型的事（M-xx）不放進來。
  • 設計稿：就是原本的設計稿頁。

檔案（省 token）

  • .crew/designs/<PRD 代號>/index.html 是固定的外框，只有標題跟著 PRD 變。內容由頁面自己讀：data.json 放清單、狀態、問題和審查結果，prd.json 放草稿全文，SCR-xxx.json 放 mockup。
  • Artifact 工具每次發佈都要帶 file_path（實測：只帶 files 會被拒），所以外框每次都會送，但內容不變；大腦讀過一次就好，之後只讀有變的 data.json、prd.json 或 mockup。新增的 data.json 和 prd.json 是產生的檔案，加進 .crew/.gitignore。

留言格式（都以「代碼」結尾）

  • 問題：「crew 回答：Q-xx」，下一行是回答。代碼是問題的指紋，所以 reset 之後重複的編號不會對到舊的問題。
  • 草稿：「crew PRD 確認：開始 <路徑>」或「crew PRD 要改：<路徑>」，下一行是要改的地方。代碼是草稿檔內容的指紋，草稿改過之後，舊頁面上按的就不算數。
  • 大腦收到開頭是「crew 」的留言，一律用 crew 工具的 decide 轉達，crew 再依開頭分派。
